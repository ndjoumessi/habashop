### ⚠️ PRÉALABLE NON NÉGOCIABLE — compter les orphelins AVANT d'écrire la migration

Ajouter une FK sur des données existantes **échoue** si une seule ligne porte un `tenantId` qui
ne correspond à aucun `Tenant`. En lecture seule, d'abord :

```sql
SELECT COUNT(*) FROM "EmployeeBonus" b
  LEFT JOIN "Tenant" t ON t.id = b."tenantId" WHERE t.id IS NULL;
SELECT COUNT(*) FROM "SalaryHistory" s
  LEFT JOIN "Tenant" t ON t.id = s."tenantId" WHERE t.id IS NULL;
```

- **0 / 0** → la migration peut être écrite et présentée.
- **> 0** → **s'arrêter** et rapporter. Il faudra décider du sort de ces lignes (rattachement ?
  suppression ?) — c'est une décision produit, pas une étape technique.

## Rituel de vérification (rappel — trois façons d'annoncer un faux « tsc 0 »)

1. **Le pipe** : `tsc --noEmit | tail` rend le statut de `tail`. Sans pipe, lire `$?`.
2. **La racine** : pas de `tsconfig.json` à la racine du monorepo → `tsc` imprime son aide.
3. **Le contexte** : `tsc` local vert ≠ build Docker vert (l'image ne copie pas `docs/`).

→ `cd apps/<ws> && npx tsc --noEmit` (sans pipe) **et** `npm run build` dans les deux workspaces.
